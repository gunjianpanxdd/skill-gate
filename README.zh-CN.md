# skill-gate

[English](./README.md) | **简体中文**

> 一个决策闸门，回答每个 Agent 团队迟早要面对的问题：
> **「这个流程要不要做成 skill？」**
> 默认答案是**不要**——而这个 skill 把这个默认答案变成可执行的流程。

Skill 是用出来的，不是设计出来的。`skill-gate` 把这条原则变成可跑的判定流程：一套七级**沉淀阶梯** + 六道可验证的**门**，流程全过了才允许封装；没过的，落到七个明确形态之一。

## 解决什么问题

没有闸门时，两种失败模式占绝对多数：

1. **封早了**——流程只真实执行了一次就封进 skill，随后返工 4 次（色板违规、变体未记录、和相邻 skill 撞路由）。
2. **封错了形态**——知识确实沉淀了，但容器选错：单页博客塞了 217 行 AGENTS.md（建完 10 分钟就撤），或者一个号称 skill 实际只是指令搬家、零机器校验的东西。

## 怎么判定

**七级沉淀阶梯**（只能逐级升，不能跳级）：

```
0 什么都不记 → 1 笔记 → 2 文档 → 3 校验脚本
→ 4 skill → 5 常驻上下文（AGENTS.md）→ 6 workflow 自动化
```

**六道门**（全过才封；第一道挂了就停）：

| 门 | 一句话判据 |
|---|---|
| 频次 | 真实执行 ≥2 次（高风险破坏性操作 1 次即可），有产物为证 |
| 稳定 | 近两次执行之间步骤无变更 |
| 边界 | description 写得出「做什么 + 何时用 + 不适用于谁」 |
| 校验 | 至少一条规则可机器判定——否则只是指令搬家，不是封装 |
| 维护 | 数得清将来要同步几处（skill 数 × 副本数 = 变更成本矩阵） |
| 触发 | agent 会在正确时机想起它，且同类场景不会先命中别的 skill |

**输出**：一张判定卡（结论 + 逐门证据 + 降级建议），经用户确认后才动手建文件。封装后 30 天内的返工记入判例库台账，作为「封早了」的证据，自动抬高下次同类判定的频次门槛。

## 目录结构

```
skill-gate/
├── SKILL.md                    # skill 入口（中文）——铁律、阶梯、六道门、判定流程、反模式
├── SKILL.en.md                 # skill 入口英文镜像
└── references/
    ├── casebook.md             # 6 个真实判例复盘 + 返工台账（中文）
    └── casebook-en.md          # 判例库英文版
```

## 安装

把 `skill-gate/` 文件夹复制到你的 agent skills 目录：

- WorkBuddy（用户级）：`~/.workbuddy/skills/skill-gate/`
- Claude Code：`~/.claude/skills/skill-gate/`

然后用类似这些说法触发：*「把这个流程做成 skill」*、*「要不要沉淀个 skill」*、
*「固化一下这个流程」*、*"should this be a skill?"*。（`SKILL.md` 是入口文件；
`SKILL.en.md` 是英文镜像，供参考。）

## 一句收束

> 第 1 次做：做。第 2 次做：记。第 3 次做：脚本。
> 第 4 次做，且以上都有产物：才谈 skill。
